# Tapgo Android

English | [中文](README.zh.md)

The Android app supports Android 8.0 and later. Its native welcome page uses the desktop mascot, name, slogans, and light/dark colors. Pair a Mac or Windows computer through its HTTPS QR code, pasted link, or `dsh-mobile` deep link. QR scanning runs on-device without Google Play services. Pairing URLs and custom computer names are encrypted with an Android Keystore key in app-private storage; backup is disabled. Web authentication cookies persist separately in WebView storage. Re-pairing the same origin retains its custom name. Removing a connection removes its saved pairing record, not Host data or an already-issued Host cookie.

The native home lists real Host sessions, supports search, recent-first order, project grouping, computer switching, rename, and connection removal. It refreshes every 15 seconds while foregrounded. Home confirmations use the same `$events` stream as iOS: allow once, reject, defer to the computer, or answer single/multiple-choice questions with an optional custom answer. The stream pings every 20 seconds and reconnects with delays capped at 30 seconds. It stops in the background or while the full workspace owns the interaction stream.

Conversations use a native transcript with Markdown, streaming replies, per-turn collapsible reasoning and tool completion states, send/stop controls, model selection, permission confirmation, and photo previews and removable attachments from the system picker. New Chat selects a registered project or registers or creates a directory and remembers the last model for each computer. Account balance is requested from the Host when available. The full Host workspace remains available for files and terminals through an origin-confined WebView. Photos use the system picker; direct camera capture and historical image rendering are not implemented. Native settings show primary-currency recharge/bonus wallets, Session token use, and available context when provided by the Host. Same-origin navigation is allowed; foreign navigation, cleartext HTTP, mixed content, local file loading, and native JavaScript bridges are disabled. A TLS error is never bypassed.

## Build

Use JDK 17, Android SDK platform 36/build tools 36.0.0, and the pinned Gradle wrapper. Set `ANDROID_HOME` or an ignored `local.properties` with `sdk.dir`. Run `./gradlew testDebugUnitTest assembleDebug lintDebug`. The debug APK is `app/build/outputs/apk/debug/app-debug.apk`; it is a test build, not a production release. `assembleRelease` produces an unsigned APK until the owning company provides an Android signing configuration. Never commit a signing key or password. The app identifier is `com.tapgo.terminal`.

## Isolated emulator tests

Use a dedicated emulator with no real pairing data. The debug-only network configuration trusts the public fixture certificate only at `localhost`; release builds contain neither that certificate nor its trust configuration. Generate a new self-signed fixture certificate and private key with DNS SAN `localhost` and IP SANs `10.0.2.2` and `127.0.0.1`, place the certificate at `app/src/debug/res/raw/fixture_ca.pem`, and keep the key outside Git. Set `TAPGO_ANDROID_FIXTURE_KEY` to the private-key path and run `node tests/fixture-server.mjs` from this directory. It atomically allocates a host loopback port and prints its readiness and assigned port and uses synthetic tokens and sessions. Forward the dedicated emulator port with `adb -s <serial> reverse tcp:9443 tcp:<printed-port>`, then run `./gradlew connectedDebugAndroidTest`; unit tests separately cover link validation and authority comparisons. Stop the fixture and emulator after testing. The fixture verifies Android transport and interaction delivery, not real-account model execution or physical-camera scanning.
